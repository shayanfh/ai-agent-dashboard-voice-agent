# Asterisk / FreePBX

The intended path is Newrock/SIP provider → Asterisk → PJSIP trunk → LiveKit SIP.
Copy and adapt these snippets into supported custom files (`pjsip_custom.conf` and
`extensions_custom.conf`). Codec, authentication, transport and LiveKit SIP address depend on
the deployment. Do not edit files generated by FreePBX.

## MixMonitor recording installation

From this repository's `deployment/asterisk` directory, create the protected recording directory
and install the uploader:

```bash
sudo install -d -o asterisk -g asterisk -m 0750 /var/spool/asterisk/monitor/ai-agent
sudo install -o root -g root -m 0755 upload-asterisk-recording.sh /usr/local/bin/upload-asterisk-recording.sh
sudo install -o root -g root -m 0755 retry-pending-asterisk-recordings.sh /usr/local/bin/retry-pending-asterisk-recordings.sh
sudo install -o root -g asterisk -m 0640 ai-agent-recording.conf.example /etc/asterisk/ai-agent-recording.conf
sudo editor /etc/asterisk/ai-agent-recording.conf
```

Copy the contexts from `extensions.example.conf` into `extensions_custom.conf`. The `b(...)`
pre-dial handler is required because `PJSIP_HEADER` must run on the outbound LiveKit channel.
If `[from-internal-custom]` already exists, add only extension `999` beneath the existing context;
do not create a second context with the same name. Also merge `direct_media=no` from
`pjsip.example.conf` into the endpoint that sends calls to LiveKit.
The example deliberately sends `1000` to LiveKit because the tested Backend mapping is
`phone_number=1000` with no extension. Keep `AI_AGENT_LIVEKIT_NUMBER` equal to that Backend value;
do not send `X-Destination-Extension` unless the same mapping has a non-empty extension.
Reload the dialplan only after validating it:

```bash
sudo asterisk -rx "dialplan reload"
sudo asterisk -rx "dialplan show from-internal-custom"
```

Keep `DELETE_AFTER_UPLOAD=false` until uploads have been verified. A separate cleanup policy can
remove old local recordings later. Never use raw caller ID in a filename or shell command.

Add a root cron entry to retry failed uploads every five minutes:

```cron
*/5 * * * * /usr/local/bin/retry-pending-asterisk-recordings.sh >> /var/log/asterisk/recording-upload.log 2>&1
```

Successful uploads are marked with a `.uploaded` sidecar when local deletion is disabled. Failed
uploads retain the WAV without a marker and are retried. After production verification, setting
`DELETE_AFTER_UPLOAD=true` removes the local WAV only after a successful Backend response.
